AgentU Setup Guide: Base URL and API Key for Every Client

AgentU is one place to manage all of your agentic spend: track it, manage it, reconcile it. Point your client at AgentU once and every call is tracked, priced against your Tariff, and recorded on a Token Detail Record you can reconcile.

Before You Start

You need an AgentU API key. Keys begin with cpk_. Keys are issued on request, so contact us to get one.

Keep the key in an environment variable or a secret store. Never paste it into a chat, a URL, or a file you commit. If a key is ever exposed, contact us to rotate it.

The Two Values You Need

Setting Value
Host https://proxy.agentu.ai
OpenAI compatible base URL https://proxy.agentu.ai/v1
Anthropic base URL https://proxy.agentu.ai (the client adds /v1/messages itself)
Preferred auth header Authorization: Bearer cpk_...
Anthropic auth header x-api-key: cpk_... also works

agentu.ai is the website. It is not an API base URL.

Check Your Setup for Free

These calls cost nothing:

curl https://proxy.agentu.ai/v1/models -H "Authorization: Bearer $OPENAI_API_KEY"
curl https://proxy.agentu.ai/v1/educateme -H "Authorization: Bearer $OPENAI_API_KEY"

/v1/models lists the exact model ids your key may call. Use only ids from that list. You can also send auto and let AgentU pick, within your account's policy. If your account requires a named model, auto is refused and you must send an exact id. The examples below use gpt-4.1-mini for OpenAI format clients and claude-haiku-4-5 for Anthropic format clients.

Grok Bot

Add AgentU as an OpenAI compatible provider with these settings:

Setting Value
Base URL https://proxy.agentu.ai/v1
Header Authorization: Bearer cpk_...
Model gpt-4.1-mini

Streaming, tool calling, and multi turn chat all work with these settings.

Other Tools

Any tool that accepts a custom base URL works the same way. Use https://proxy.agentu.ai/v1 with your cpk_ key if the tool speaks the OpenAI format, or https://proxy.agentu.ai if it speaks the Anthropic format. Then pick a model id from /v1/models.

OpenAI Compatible Clients

Environment Variables

export OPENAI_BASE_URL="https://proxy.agentu.ai/v1"
export OPENAI_API_KEY="cpk_your_key"

curl

curl https://proxy.agentu.ai/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4.1-mini", "messages": [{"role": "user", "content": "Hello"}], "max_tokens": 100}'

Python

from openai import OpenAI

client = OpenAI()  # reads OPENAI_BASE_URL and OPENAI_API_KEY
reply = client.chat.completions.create(
    model="gpt-4.1-mini",
    messages=[{"role": "user", "content": "Hello"}],
    max_tokens=100,
)
print(reply.choices[0].message.content)

Node

import OpenAI from "openai";

const client = new OpenAI(); // reads OPENAI_BASE_URL and OPENAI_API_KEY
const reply = await client.chat.completions.create({
  model: "gpt-4.1-mini",
  messages: [{ role: "user", content: "Hello" }],
  max_tokens: 100,
});
console.log(reply.choices[0].message.content);

Anthropic Clients

Environment Variables

export ANTHROPIC_BASE_URL="https://proxy.agentu.ai"
export ANTHROPIC_API_KEY="cpk_your_key"

Leave /v1 off. The client adds /v1/messages itself.

curl

curl https://proxy.agentu.ai/v1/messages \
  -H "x-api-key: $ANTHROPIC_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "claude-haiku-4-5", "max_tokens": 100, "messages": [{"role": "user", "content": "Hello"}]}'

Python

import anthropic

client = anthropic.Anthropic()  # reads ANTHROPIC_BASE_URL and ANTHROPIC_API_KEY
reply = client.messages.create(
    model="claude-haiku-4-5",
    max_tokens=100,
    messages=[{"role": "user", "content": "Hello"}],
)
print(reply.content[0].text)

Node

import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic(); // reads ANTHROPIC_BASE_URL and ANTHROPIC_API_KEY
const reply = await client.messages.create({
  model: "claude-haiku-4-5",
  max_tokens: 100,
  messages: [{ role: "user", content: "Hello" }],
});
console.log(reply.content[0].text);

Optional Headers for Cleaner Reconciliation

Send these on every call to group spend:

Header What it records
x-proxy-subclient The project the work belongs to
x-proxy-app The role or app making the call
x-proxy-project A free text tag for grouping work
x-proxy-department A department slug from GET /v1/departments

See What You Spent

GET /v1/spend?days=30 shows totals by model, department, and project. GET /v1/usage/{request_id} shows the rated record for one call. Both are free. If no spending cap is set on your account, spend is not limited. If a cap is set, calls past it are refused with a 429 quota_exceeded error.
