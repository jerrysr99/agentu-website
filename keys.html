Connect an app to the proxy

Every route below lands on the same place: your account, your department, your spend limits, one TDR per call. Pick the one your app supports.

1. Apps that connect with a sign-in (MCP)

Claude Desktop and other MCP clients. Nothing to paste: add the URL, then sign in and choose a role when prompted.

MCP server URL
https://mcp.jerrywlambert.com/mcp

You choose which of your own keys the app mirrors. It gets its own new key named for that app, carrying the same department and role as the one you picked, so a connected app can never reach further than you can. It appears under Proxy keys. Revoke it there to disconnect the app and nothing else.

2. Apps that take a custom header

Use your own proxy key. Some apps reserve Authorization for their own sign-in, which is why the second form exists.

Header name
x-api-key
Header value
cpk_… (your key, no prefix)
Or header name
Authorization
Value
Bearer cpk_…

Either works. Do not put Bearer in front of the value when the header is x-api-key.

3. Coding clients and SDKs

Claude Code, Cline, Continue, Aider, Zed, the OpenAI and Anthropic SDKs. Point the base URL at the proxy and change nothing else.

Base URL
https://agentu.jerrywlambert.com
API key
cpk_… (your key)

Both dialects are served natively: /v1/messages (Anthropic) and /v1/chat/completions (OpenAI).

What does not work, and why

Cursor and GitHub Copilot's in-IDE agent modes broker the model on their own backend and offer no way to point them at another endpoint, so their spend cannot be governed here. GitHub Copilot CLI and Copilot in GitHub Desktop do support it, via their BYOK settings, using the base URL above. We would rather say so than let you discover it in a pilot.
